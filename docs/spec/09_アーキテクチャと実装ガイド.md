## 2. 起動シーケンス

1. WordPressが `employee-manager.php` を読み込む。
2. 定数定義: `EMP_VERSION`(1.2.1)、`EMP_PLUGIN_DIR`、`EMP_PLUGIN_URL`、`EMP_PLUGIN_FILE`。
3. `includes/*` と `admin/class-admin-menu.php` を `require_once`。
4. `register_activation_hook` → `EMP_DB_Install::activate`／`register_deactivation_hook` → `deactivate`（何もしない）。
5. `plugins_loaded` で `emp_init()`: オプション `emp_db_version` ≠ `EMP_VERSION` なら `activate()`（テーブル更新＋履歴補完）。
6. `is_admin()` のときのみ `new EMP_Admin_Menu()`:
   - `admin_menu` → メニュー登録（権限 `access_custom_plugins`）
   - `admin_enqueue_scripts` → 本プラグインの5ページのみ CSS/JS を読み込み、`empData` を `wp_localize_script`
   - AJAXフックを一括登録

## 3. 画面とJS
- `admin.js` は IIFE で、画面固有ブロックを **ルート要素のID** で分岐: `#emp-list-page`／`#emp-form-page`／`#emp-master-page`／`#emp-csv-page`／`#emp-import-page`。
- 共通関数: `empAjax(action, data, cb)`（`$.post` ラッパ）、`showToast(msg, type)`、`escHtml`、`escAttr`。
- 社員一覧: 状態はクロージャ変数（`currentPage, perPage, sortCol, sortDir, selectedIds`）。
- 社員フォーム: 編集データは `data-emp-json` 属性から読み、`fillForm()` で復元。送信時 `collectFormData()` が動的行を配列化。
- CSV出力: `checkedKeys`（Set）と `columnOrder`（配列）が状態。実行時は隠しフォームをPOST。
- インポート: `parsedRowsMap`（種別→行配列）。解析はブラウザ内。

## 4. 主な処理フロー

### 4-1. 社員保存
```
フォーム送信 → collectFormData() → AJAX emp_employee_save {id, data}
  → EMP_Employee::ajax_save(): nonce検証・edit権限
    → save($data, $id)
        検証(必須/一意/乗組員コード) → START TRANSACTION
        → emp_master INSERT/UPDATE → sync_crew_code_history() → COMMIT
        → save_insurance / save_retirement (upsert)
        → save_children ×4 (全削除→再挿入)
    → JSON {id, message}
  → 一覧へリダイレクト(emp_saved=1)
```

### 4-2. 乗組員コード追加
`#crewHistoryAdd` → AJAX `emp_crew_history_add` → `add_current_crew_code()`（検証→トランザクション→master更新→履歴同期）→ 画面リロード。

### 4-3. CSV出力
`#csvExportBtn` → 隠しフォームPOST（`emp_csv_export`）→ `ajax_export()`（入力検証）→ `output()`:
列検証(`valid_column_keys`)→ 列定義の順序化 → `fetch_data()`（必要なJOINのみ）→ ヘッダ送出 → 1行ずつ `write_row()`（`fputcsv`→CRLF統一→SJIS変換→数式対策）→ `exit`。

### 4-4. CSVインポート
ファイル選択 → JS解析 → プレビュー → 実行 → AJAX `emp_csv_import` → `import_basic/career/dependent` → 結果JSON。

## 6. 開発メモ（READMEより＋コード確認）
- PHP 8.0の `match`・名前付き引数・Union型は意図的に未使用（後方互換重視）。ただし `fn` アロー関数（PHP 7.4+）、`??` は使用。
- JavaScriptは jQuery のみ。外部ライブラリなし。
- DBマイグレーションは `dbDelta` 依存。`create_tables()` を修正し `EMP_VERSION` を上げれば、次回アクセス時に自動実行される。
- 関連テーブルの全削除→再挿入という保存方式のため、関連テーブルの `id` は保存のたびに変わる。他テーブルから関連行IDを参照する設計にしないこと。

## 7. デプロイ [コード確認（ワークフロー）／リポジトリ外（サーバー詳細）]
- `master` へ push → GitHub Actions `deploy.yml` が `SamKirkland/FTP-Deploy-Action` で本番サーバーのプラグインディレクトリへFTP転送。
- `staging` へ push → `staging-deploy.yml` が検証サーバーへ転送。
- 接続情報は GitHub Secrets（`FTP_HOST_*`, `FTP_USER_*`, `FTP_PASS_*`）。**コードに書かない**。
- `dangerous-clean-slate: false` のため、サーバー側の余分ファイルは削除されない。
- リポジトリ全体（`./`）が転送対象のため、`README.md`・`index.html`・`引き継ぎ書*.md` 等もサーバーに置かれる。機密情報をリポジトリに入れない。
- 推奨フロー: 機能ブランチ → `staging` へマージで検証 → 問題なければ `master` へPR/マージ（履歴は `Merge pull request #n from ims-hirosaki/staging` の形）。

## 8. 外部システムとの結合 [リポジトリ外：引き継ぎ書]
- **勤怠管理プラグイン**: `emp_get_*` と乗組員コード履歴APIを利用。テーブル `am_chokyo_kintai_log` / `am_chokyo_carryover` に `employee_id` を保持。
- **拘束時間インポーター**: 外部Excelを読んで `kousoku_log` に保存し、`emp_crew_code_history` で `乗組員コード＋勤務日` を社員へ紐づける。`kousoku_log` は外部原本のため、コード変更時に書き換えない方針。未紐づけは保存して警告。
- 乗組員コードを変更・履歴修正する際は、上記システムの集計に影響しうるため、運用ルール（変更日・時点）を事前に確認すること。

## 9. 改修時のチェックリスト
1. 項目追加: DB（`class-db-install.php`）→ 保存（`EMP_Employee::save` / `$master` 配列）→ フォーム（`employee-form.php` と `admin.js` の収集・復元）→ CSV出力（`column_definitions` とグループ定義 `csv.php`、PRESETS）→ CSVインポート（列定義とひな形、プレビュー列）→ 公開API の SELECT → 本仕様書。
2. 1:多テーブル追加: `save_children` の利用、`get_by_id` への追加、`delete()` の `$related` への追加、`drop_tables()` への追加。
3. 権限追加: `admin-menu`・AJAXハンドラ・UI出し分け・`08`。
4. 乗組員コード関連の変更: `validate_new_crew_code`、`validate_history_period`、`sync_crew_code_history`、インポートの扱い、公開API、勤怠側への影響を確認。
5. バージョンを上げる場合: `employee-manager.php` のヘッダ `Version` と `EMP_VERSION` の**両方**を更新（不一致だとマイグレーションが毎回走る）。
6. テスト: 自動テストは存在しない。staging で手動確認（`11` の確認観点参照）。

## 10. ログとデバッグ
- `WP_DEBUG_LOG` 有効時、`wp-content/debug.log` に `[EMP]` ログ（保存失敗時のDBエラー等）。
- インポートは受信行数と先頭行（JSON）を常に `error_log` に出力する（`[EMP_Import]`）。**先頭行には個人情報が含まれる**ため、ログの管理に注意。
