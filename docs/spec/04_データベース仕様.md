# 04 データベース仕様

- 読者: エンジニア
- 定義元: `includes/class-db-install.php`（`EMP_DB_Install::create_tables()`）。`dbDelta()` で作成・更新。
- テーブル接頭辞: `{prefix}` = `$wpdb->prefix`（通常 `wp_`）
- 文字セット: `$wpdb->get_charset_collate()`
- 全13テーブル。外部キー制約（FOREIGN KEY）は**定義されていない**。関連はアプリケーションが `employee_id` 等で維持する。 [コード確認]

## 2. ER図（論理）

```
mst_affiliation ─┐
mst_department  ─┤ (id)  ←  emp_master.affiliation_id / department_id / position_id / job_type_id
mst_position    ─┤
mst_job_type    ─┘

emp_master (id) ─┬─ 1:1  emp_insurance       (employee_id UNIQUE)
                 ├─ 1:1  emp_retirement      (employee_id UNIQUE)
                 ├─ 1:多 emp_education       (employee_id)
                 ├─ 1:多 emp_career          (employee_id)
                 ├─ 1:多 emp_qualification   (employee_id)
                 ├─ 1:多 emp_dependent       (employee_id)

wp_users (ID) ── 1:多 emp_csv_template (wp_user_id)
```

## 3. 共通カラム

ほぼ全テーブルに `created_at`（DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP）と `updated_at`（同＋ON UPDATE CURRENT_TIMESTAMP）がある。ID（主キー）は AUTO_INCREMENT。

## 4. マスタ4テーブル（共通構造）

`mst_affiliation`／`mst_department`／`mst_position`／`mst_job_type`

| カラム | 型 | 説明 |
|---|---|---|
| id | INT UNSIGNED PK AUTO_INCREMENT | |
| name | VARCHAR(100) NOT NULL | 名称（所属名・部署名など） |
| sort_order | SMALLINT NOT NULL DEFAULT 0 | 表示順（小さい順） |
| is_active | TINYINT(1) NOT NULL DEFAULT 1 | 1=有効 0=無効 |
| created_at / updated_at | DATETIME | 共通 |

- 名称のUNIQUE制約はない（同名の登録が可能）。
- 並び: `ORDER BY sort_order ASC, id ASC`。

## 5. `emp_master`（社員マスタ）

| カラム | 型 | NULL | 説明 |
|---|---|---|---|
| id | INT UNSIGNED PK | NOT NULL | 内部ID（サロゲートキー）。他テーブルの `employee_id` の参照先 |
| employee_code | VARCHAR(20) | NOT NULL | 社員コード。**UNIQUE**（`uq_employee_code`） |
| affiliation_id | INT UNSIGNED | NULL | 所属ID（mst_affiliation.id） |
| department_id | INT UNSIGNED | NULL | 部署ID |
| position_id | INT UNSIGNED | NULL | 役職ID |
| job_type_id | INT UNSIGNED | NULL | 職種ID |
| employment_type | VARCHAR(20) | NULL | 雇用区分（正社員／契約社員／パート・アルバイト） |
| weekly_work_days | TINYINT | NULL | 週勤務日数（1〜6） |
| crew_code | VARCHAR(20) | NULL | **現行**の乗組員コード（NULL=乗務員でない）。履歴は別テーブル |
| name | VARCHAR(100) | NOT NULL | 氏名 |
| name_kana | VARCHAR(100) | NULL | フリガナ |
| gender | VARCHAR(10) | NULL | 性別（男性／女性／その他） |
| birthdate | DATE | NULL | 生年月日 |
| blood_type | VARCHAR(5) | NULL | 血液型 |
| my_number | VARCHAR(255) | NULL | 個人番号。**コメントは「暗号化推奨」だが現状は平文保存** |
| hire_date | DATE | NULL | 入社日 |
| zip | VARCHAR(10) | NULL | 郵便番号 |
| address | VARCHAR(255) | NULL | 住所 |
| tel_home / tel_mobile / tel_company | VARCHAR(20) | NULL | 自宅／携帯／会社携帯 |
| emergency_name | VARCHAR(100) | NULL | 緊急連絡先氏名 |
| emergency_tel | VARCHAR(20) | NULL | 緊急連絡先電話 |
| emergency_relation | VARCHAR(50) | NULL | 緊急連絡先続柄 |
| memo | TEXT | NULL | 総合備考 |
| is_active | TINYINT(1) | NOT NULL DEFAULT 1 | 在籍フラグ 1=在籍 0=退職 |
| created_at / updated_at | DATETIME | | |

インデックス: PK(id)、UNIQUE(employee_code)、`idx_affiliation`(affiliation_id)、`idx_department`(department_id)、`idx_is_active`(is_active)。

補足:
- 画面（フォーム）経由の保存では、空の任意項目は **NULL** で保存される。CSVインポート経由では一部の文字列項目が **空文字 ''** で保存される（`06` 参照）。比較・集計時は両方を考慮すること。 [コード確認]
- `crew_code` に UNIQUE制約はないが、アプリ側で他社員の現行コード・履歴と重複しないよう検証している（`05`）。

## 6. `emp_crew_code_history`（乗組員コード履歴）

| カラム | 型 | NULL | 説明 |
|---|---|---|---|
| id | BIGINT UNSIGNED PK | NOT NULL | |
| employee_id | INT UNSIGNED | NOT NULL | emp_master.id |
| crew_code | VARCHAR(20) | NOT NULL | 乗組員コード |
| valid_from | DATE | NULL | 適用開始日。NULL=開始日の制限なし |
| valid_to | DATE | NULL | 適用終了日。NULL=終了日の制限なし（現行は常にNULL） |
| is_current | TINYINT(1) | NOT NULL DEFAULT 0 | 1=現行コード |
| created_by / updated_by | BIGINT UNSIGNED | NULL | 作成/更新した WordPress ユーザーID |
| created_at / updated_at | DATETIME | | |

インデックス: PK(id)、**UNIQUE(employee_id, crew_code)**、`idx_employee_period`(employee_id, valid_from, valid_to)、`idx_code_period`(crew_code, valid_from, valid_to)、`idx_current`(employee_id, is_current)。

重要な不変条件（アプリが保証）:
- 1社員につき `is_current=1` は高々1行。その `crew_code` は `emp_master.crew_code` と一致。
- 同一社員の期間は重ならない。**別社員の同一コードとも期間が重ならない**。
- 期間の NULL は「無限」として扱う（NULL 開始＝いつからでも、NULL 終了＝いつまでも）。
- 同一社員で同じコードは1行のみ（UNIQUE）。したがって「過去に使ったコードを再び使う」ことは通常操作ではできない。

初期補完: `EMP_DB_Install::backfill_current_crew_codes()` が、有効化時に `emp_master.crew_code` が空でない社員のうち履歴に無いものを `valid_from=NULL, valid_to=NULL, is_current=1` で挿入する（再実行可能）。続けて、master の現行値と一致する履歴は `is_current=1`、一致しないものは 0 に再設定する。

## 8. 1:多 テーブル（共通: `employee_id` NOT NULL＋インデックス `idx_employee`、`sort_order` SMALLINT DEFAULT 0）

### `emp_education`（学歴）
graduation_date DATE（卒業年月日）／school_name VARCHAR(200)（学校名）／department VARCHAR(200)（学科・専攻）

### `emp_career`（職歴）
career_year CHAR(4)（年）／career_month CHAR(2)（月）／company_name VARCHAR(200)／department VARCHAR(200)／position VARCHAR(200)／memo TEXT（備考）

### `emp_qualification`（免許・資格）
name VARCHAR(200)（資格・免許名）／acquired_date DATE（取得日）

### `emp_dependent`（扶養者）
name VARCHAR(100)（氏名）／name_kana VARCHAR(100)／relation VARCHAR(50)（続柄）／birthdate DATE／memo TEXT

保存方式: 社員フォームの保存では、これら4テーブルは**社員単位で全削除→画面の行を再挿入**（`sort_order` は画面の行順 0,1,2…）。CSVインポート（②③）は**追記のみ**（`sort_order` は常に0）。 [コード確認]

## 10. その他のWordPressデータ

- オプション `emp_db_version`: 最後にマイグレーションを実行したプラグインバージョン（`EMP_VERSION` と比較して不一致なら `activate()` を再実行）。

## 11. ライフサイクル

| イベント | 処理 |
|---|---|
| 有効化 | `EMP_DB_Install::activate()`: テーブル作成（dbDelta）→ 乗組員コード履歴の補完 → `emp_db_version` 更新 |
| 無効化 | 何もしない（データ保持） |
| 起動時（`plugins_loaded`） | `emp_db_version` が `EMP_VERSION` と違えば `activate()` を再実行（カラム追加等の自動マイグレーション） |
| 削除（uninstall） | `drop_tables()`: 全13テーブルを DROP し、`emp_db_version` を削除。**元に戻せない** |

カラム追加の手順: `create_tables()` の該当 `CREATE TABLE` を修正し、`EMP_VERSION` を上げる（またはプラグインを再有効化）。`dbDelta` の書式制約（PRIMARY KEY の前に2スペース等）に注意。

## 12. データ取得時の結合（参照用）

社員1件取得（`EMP_Employee::get_by_id`）が返すオブジェクトの構造:
```
emp_master の全カラム
 + affiliation_name / department_name / position_name / job_type_name  （マスタとLEFT JOIN）
 + insurance          : emp_insurance の1行（なければ null）
 + retirement         : emp_retirement の1行（なければ null）
 + educations[]       : emp_education（sort_order, id 順）
 + careers[]          : emp_career
 + qualifications[]   : emp_qualification
 + dependents[]       : emp_dependent
 + crew_code_history[]: 履歴（現行が先頭、次に開始日の新しい順）
```
