## 1. 社員の保存ルール（`EMP_Employee::save()`）

### 1-1. 必須・一意
| ルール | 内容 | エラーメッセージ |
|---|---|---|
| 社員コード必須 | 空は不可 | 社員コードは必須です |
| 氏名必須 | 空は不可 | 氏名は必須です |
| 社員コード一意 | 自分以外に同じ社員コードがあれば不可（編集時は自分自身を除外して判定） | この社員コードはすでに使用されています |

### 1-2. サニタイズ・型
- 文字列は `sanitize_text_field`（メモは `sanitize_textarea_field`）。空文字は NULL に変換して保存。
- 日付: `YYYY-MM-DD` 形式かつ実在日のみ有効。**不正な日付は黙って NULL になる**（エラーにならない）。
- ID系（所属など）: 値があれば整数化、なければ NULL。
- `weekly_work_days`: 値があれば整数化、なければ NULL（範囲チェックなし。画面は1〜6のみ）。
- `is_active`: 未指定は 1（在籍）。
- 値の選択肢（性別・血液型・雇用区分など）はサーバー側で**検証しない**（画面のプルダウンに依存）。

### 1-3. 保存の流れ
1. 検証（上記＋乗組員コード検証）
2. トランザクション開始 → `emp_master` を UPDATE／INSERT → 乗組員コード履歴を同期 → COMMIT（失敗時 ROLLBACK）
3. トランザクション**外**で 保険・退職を upsert、学歴/職歴/資格/扶養者を全削除→再挿入
   - 3 の失敗はログ（`error_log` の `[EMP]` プレフィックス）に出るだけで、画面には成功と返る可能性がある。 [コード確認]
4. 社員ID（`employee_id`）を返す。

### 1-4. 在籍フラグと退職日
- 在籍フラグ（`emp_master.is_active`）と退職日（`emp_retirement.retirement_date`）は**独立**。互いに自動更新されない。
- 退職処理は「在籍フラグを退職（0）にする」＋必要なら「退職日を入力」の2点を行う。
- 在籍フラグのみの切替は `toggle_active()`（一覧のクリック・一括操作）。

### 1-5. 削除
- `EMP_Employee::delete($id)` は存在する（関連テーブルも物理削除）が、**画面にもAJAXにも接続されていない**。通常運用では使えない。

## 2. 乗組員コード履歴のルール

### 2-1. 考え方
- 乗組員コードは変わりうる。過去のコードで記録された外部データ（勤怠等）を同じ社員に結びつけるため、**使用期間つきで全コードを残す**。
- 社員は不変の内部ID（`emp_master.id`）で識別し、コードは期間で「その時点の社員」に対応づける。
- 現行コードは `emp_master.crew_code` にも持つ（`emp_crew_code_history.is_current=1` の行と一致）。

### 2-2. 新規社員の初回コード
- 登録フォームの「初回乗組員コード」（任意）。入力すると `valid_from=登録日（サイト時刻の日付）`、`valid_to=NULL`、`is_current=1` で履歴を作成。
- 空欄なら乗務員ではない扱い（`crew_code=NULL`、履歴なし）。

### 2-3. 既存社員のコード変更（唯一の経路）
操作: 社員編集 → 乗組員コード履歴 → 新コード入力 → 「新規コードを追加」（`emp_crew_history_add`、権限 `edit_custom_plugins`）。

処理（`add_current_crew_code`）:
1. 新コードを検証（下記エラー）。
2. `valid_from = 本日`（サイト時刻）。
3. トランザクション: `emp_master.crew_code` を新コードに更新 → 履歴同期:
   - その社員の履歴の `is_current` をすべて 0 に
   - 旧コードの行の `valid_to = 本日の前日`（旧コード行がなければ `valid_from=NULL` で作成）
   - 新コードの行を `valid_from=本日, valid_to=NULL, is_current=1` で挿入
4. 成功: 「新しい乗組員コードを追加しました（使用開始日：YYYY-MM-DD）」。

通常の社員保存（`emp_employee_save`）では、**既存社員のフォーム上の乗組員コードは無視**され、現行コードが維持される。

### 2-4. 履歴の期間修正（管理権限のみ）
操作: 履歴行の「期間を保存」（`emp_crew_history_update`、権限 `manage_custom_plugin_settings`）。
- 現行行: コード・終了日は変更不可（コードは強制的に既存値、終了日は NULL）。開始日は変更可。
- 過去行: コード・開始日・終了日を変更可。
- 検証: コード必須／開始日≦終了日／期間重複なし（`validate_history_period`）。
- 変更した過去行のコードは `emp_master.crew_code` に影響しない。
- **削除機能はない。**

### 2-5. 期間重複の判定
2つの期間 [from1, to1] と [from2, to2] は、次を両方満たすとき重複とみなす（NULLは無限）:
`from2 ≦ to1`（to1が無限ならTRUE）かつ `to2 ≧ from1`（from1が無限ならTRUE）。
- 同一社員の別行と重なる → 「この社員の別の乗組員コード履歴と使用期間が重複しています」
- 別社員の同じコードの行と重なる → 「この乗組員コードは同じ期間に別の社員が使用しています」

### 2-6. CSVインポートとの関係
- 既存社員: CSVの乗組員コードが現行と異なる（空欄含む）場合、**変更せず**エラー表示（他の項目は更新）。
- 新規社員: CSVのコードが他社員の現行コードや履歴に存在すれば、**空欄で登録**してエラー表示。使えるコードなら登録後に履歴を補完（`ensure_current_crew_code_history`、`valid_from=NULL`）。

### 2-7. 公開APIでの期間取得
`emp_get_crew_codes_for_period($employee_id, $start, $end)`: 指定期間と重なる履歴行を開始日順に返す。履歴行が1件もなければ、`emp_master.crew_code` を `valid_from=null, valid_to=null, is_current=1` として返す（フォールバック）。日付が不正／開始>終了なら空配列。

## 4. マスタ管理のルール（`EMP_Master`）
- 種別は `affiliation` / `department` / `position` / `job_type` の4つ。それ以外は拒否/空配列。
- 名称は `sanitize_text_field`。同名の重複登録は**防止されない**。
- 削除前に `emp_master` の該当ID列の使用件数を確認し、1件以上なら拒否。※CSV等の他テーブルは確認しない。
- 更新は渡された項目のみ（name / sort_order / is_active）。更新項目が無いと失敗扱い。
- 公開API（`emp_get_affiliations()` など）は**有効なものだけ**を返す。管理画面AJAX（`emp_master_get_list`）は**無効を含む全件**を返す。
