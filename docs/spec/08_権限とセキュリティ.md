# 08 権限とセキュリティ

- 読者: システム管理者・エンジニア
- 本システムは**個人情報（氏名・住所・生年月日・保険番号・個人番号・扶養者等）**を扱う。

---

## 1. 権限（capability）モデル [コード確認]

本プラグインは3つのカスタム権限を使う。

| 権限 | 意味 | 使われる場所 |
|---|---|---|
| `access_custom_plugins` | 画面を開く・参照する（閲覧レベル） | 全メニュー・全ページ表示、一覧/1件取得/統計/マスタ一覧/CSV出力/CSVテンプレート一覧/ひな形DL |
| `edit_custom_plugins` | データを変更する（編集レベル） | 社員保存・在籍切替・乗組員コード追加・マスタ登録/更新/削除・CSVテンプレート保存/更新/削除・CSVインポート実行 |
| `manage_custom_plugin_settings` | 設定管理（管理者レベル） | 乗組員コード履歴の期間修正（画面の編集UI表示と `emp_crew_history_update`） |

- **これらの権限を WordPress ロールに割り当てる処理は、このリポジトリには含まれない。** コミットメッセージ・READMEによれば「共通 mu-plugin のカスタムケイパビリティ」で管理されている（`wp-content/mu-plugins/` 側）。どのロール（ユーザー）にどの権限があるかは、このリポジトリからは分からない。 [リポジトリ外]
- 以前（初期版）は全メニューが `manage_options`（WordPress管理者）だった。READMEには古い記述が残っている（`11` 参照）。
- 権限なしで画面URLを直接開くと「権限がありません。」（HTTP 403）。AJAXは `-1` を返す。

### 権限と操作の対応表
| 操作 | 必要権限 |
|---|---|
| メニュー表示・社員一覧・検索・統計 | access |
| 社員の詳細表示（編集画面を開く） | access |
| **CSV出力（全社員の個人情報を含む出力）** | access（**編集権限不要**） |
| 社員登録・更新・在籍/退職の切替 | edit |
| 乗組員コードの追加 | edit |
| 乗組員コード履歴の期間修正 | manage |
| マスタの追加・変更・削除 | edit |
| CSVインポート（①②③） | edit |
| CSVテンプレートの保存・変更・削除 | edit |

### 画面上の出し分けについて
- 編集権限が無いユーザーにも、**編集ボタン・在籍切替・登録ボタンなどは画面に表示される**。クリックすると保存はサーバーで拒否される（UI側の非表示制御は、乗組員コード履歴の編集UI以外には実装されていない）。
- 乗組員コード履歴の編集UI（「期間を保存」ボタン）は、`manage_custom_plugin_settings` を持つ場合のみ表示される。

## 2. 実装されているセキュリティ対策 [コード確認]

| 対策 | 内容 |
|---|---|
| ダイレクトアクセス防止 | 各PHPの先頭で `ABSPATH` 未定義なら `exit` |
| CSRF対策 | すべてのAJAXで nonce 検証（`check_ajax_referer`）。nonce種別: `emp_master_nonce`, `emp_employee_nonce`, `emp_csv_nonce`, `emp_import_nonce` |
| 認証 | `wp_ajax_*` のみ（未ログイン不可）＋ capability チェック |
| SQLインジェクション対策 | `$wpdb->prepare`、`$wpdb->insert/update/delete`（書式指定付き）。並べ替え列・種別は許可リスト方式（`orderby`、マスタ種別、CSV列キー） |
| 出力エスケープ | PHPビューは `esc_html`/`esc_attr`/`esc_url`。JSは `escHtml`/`escAttr` で描画 |
| CSV数式インジェクション対策 | 出力時、`= + - @` で始まる値の先頭に `'` を付与 |
| 入力サニタイズ | `sanitize_text_field` ほか。日付は厳密形式のみ |
| 他ユーザーのテンプレート保護 | テンプレートの更新・削除・取得は `wp_user_id` 条件つき |
| HTTPヘッダ | CSV出力に `X-Content-Type-Options: nosniff`、キャッシュ無効化 |
| アンインストール保護 | `WP_UNINSTALL_PLUGIN` 未定義なら `exit` |
| デバッグログ | CSV出力は `WP_DEBUG` 時のみ。個人データは出さない設計 |

## 3. 注意が必要な点（リスクと推奨対応） [コード確認／推測]

| # | 内容 | 影響 | 推奨 |
|---|---|---|---|
| 1 | **マイナンバー（`my_number`）は暗号化されず平文でDB保存**。画面のヒントは「保存時は暗号化されます」で実装と食い違う。編集時にはパスワード欄に平文が復元され、HTML属性（`data-emp-json`）にも出力される。公開API（`emp_get_employee_by_id`）や `emp_employee_get_one` の応答にも含まれる | 個人番号の漏えいリスク | 暗号化の実装（READMEの今後の拡張ポイントにも記載）。実装までは入力しない運用、画面文言の修正を検討。法令（番号法）上の安全管理措置の観点で要検討 |
| 2 | CSV出力が閲覧権限（access）だけで可能 | 全社員の個人情報を一括取得できる | 権限設計の見直し、または出力を edit/manage 以上に限定 |
| 3 | 画面上で編集系UIが閲覧専用ユーザーにも表示される | 誤操作・混乱（保存はサーバーで拒否） | UI出し分けの実装 |
| 4 | 学歴/職歴/資格/扶養者の保存で、クライアントから来た行のキーをそのまま列名に使う | 想定外キーでINSERT失敗（権限者のみ操作可。SQLインジェクションにはならない：値は `wpdb->insert` が準備） | 許可キーの固定化 |
| 5 | 社員の更新履歴（誰がいつ何を変更したか）が残らない（乗組員コード履歴の作成者/更新者IDのみ） | 監査・不正調査が困難 | 変更履歴ログの追加（READMEの拡張ポイント） |
| 6 | `EMP_Employee::delete()`（物理削除）が存在するが、画面・AJAXから呼べない | 現状は影響なし。将来つなぐ場合は権限・確認・履歴が必要 | — |
| 7 | プラグインを「削除」すると全データが即時にDROPされる | データ消失 | 削除前にDBバックアップ。無効化だけならデータは残る |
| 8 | ひな形ダウンロードURLに nonce が含まれる（GET） | 低リスク（ログインユーザー限定） | — |
| 9 | CSVのインポートは行ごとに確定（全体ロールバックなし） | 途中エラーで一部のみ反映 | プレビュー確認・分割取り込み |
| 10 | サーバー運用上の秘匿情報（DB接続・SSH・FTP）はこのリポジトリに含めない方針。デプロイ用の認証情報は GitHub Secrets を使用 | — | Git管理しない。引き継ぎ書に平文で書かない |

## 4. 個人情報の保護の観点（運用ガイド）
- 画面・CSVを扱う担当者を最小限にし、権限を適切に割り当てる（特に access＝CSV出力可）。
- CSV出力ファイルは、保存先・共有範囲・保管期間を決めて管理する（出力時に透かし等は付かない）。
- ステージング環境に本番データをコピーする場合は、個人情報の取り扱いに注意（引き継ぎ書の方針: 本番DBを毎日stagingへ丸ごと上書きする運用は不採用）。 [リポジトリ外]
- バックアップは暗号化・アクセス制限をかける。
